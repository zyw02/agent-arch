# Source-informed DSH / OpenClaw comparison and evidence reuse

This investigation precedes new native experiments. It binds DSH `dsh-v0.2.2-alpha.2` (`f3803c96974ad4a94195fb97e5c637e9c2a3afe3`) and the existing OpenClaw `2026.10.7` campaign (`157d8c2bc3ea2fa183afdc11088e69690bf8e64e`). The DSH source tag resolves to that commit; association with the installed npm runtime still needs build/package calibration. The current OpenClaw release is now `2026.10.8` (`dc2523e5a5c7a309517fd7fa834add938231d526`). The [version bridge](evidence/source-informed-20261028/version-bridge.json) checks all 14 selected OpenClaw source files: their blobs are unchanged from 10.7. This is source continuity only, not whole-program/runtime equivalence; new calibration uses 10.8 and old results keep 10.7 labels. DSH npm `latest` currently selects `0.2.1-rc.2`; the explicitly selected 0.2.2-alpha.2 channel remains separately declared. The local product checkouts were older and are excluded from these source findings. [Source manifest](source-review-manifest.json) records 38 fetched pinned files and Git blob identities; it is not an assertion that every possible implementation was exhaustively reviewed.

The historical campaign was re-audited using its original validator: **257 scenarios, 253 measured scenarios, 969 accepted measured observations, four verified capability exclusions**. This is 60 experiment families, not 257 independent experiment families. The 29 scenarios retaining failed acceptance are retained as evidence. Invalid/quarantined originals and calibration are excluded. [Reuse audit](evidence/source-informed-20261028/reuse-audit.md) maps all scenarios to candidate questions and permanent ZIP hashes without giving them new-comparison coverage credit.

## Reuse decisions

1. **Reuse as accepted historical mechanism evidence:** preserve original scenario/unit IDs, product version, controller, acceptance assertions and original archive hashes. This can avoid redoing OpenClaw lifecycle, authority, telemetry-fault and recovery probes where the question is identical.
2. **Recover fields for quantitative reuse:** compact records often contain assertions rather than resource values. Read only hash-verified original summaries on disposable hosted workers, then check workload, grant, model, topology, clock and counter semantics. Missing CPU/time/token fields remain unknown.
3. **Reuse fixtures/controls while supplementing observations:** add peer OS/session witnesses for restore scope, skill/context payload attribution, and source-linked decision traces. Record supplements as new runs instead of rewriting old evidence.
4. **New mechanisms require new experiments:** COST-03's model-written `AGENTS.md` reuse does not complete Skill Workshop automatic review, sealed transfer/regression or native version reversal. Its real provider accounting is still useful for learning/reuse cost and stale-rule behavior.
5. **Cross-product resource comparisons require matched conditions:** old OpenClaw bounded hosts, task deadlines, model settings and different workloads cannot automatically become the baseline for a new DSH task. Retain old results as context when conditions differ.

No family is repeated merely because an original workflow has a collection-step failure: accepted records and retained evidence identity govern reuse. Verified unsupported scopes remain capability findings; incomplete adapters remain unfinished work.

## Work now underway

`audit_reuse.py` has revalidated the full historical campaign and emitted a scenario-level reuse/provenance inventory. `inspect_reuse_archives.py` starts with four relevant historical families—COST-03, COST-07, OBS-02 and REL-10—on disposable hosted workers. It reads ZIPs in memory, checks their permanent hashes and finds native summaries by the exact digest referenced by accepted records. It emits a bounded numeric-field inventory; this is extraction preparation, not yet a normalized resource ledger or a new experiment result.

Next, bind the actual DSH published headless profile and native tool/MCP schemas, validate one same-operation end-to-end adapter, then extend only the missing controls identified above. The common time/token/CPU/memory/disk ledger and figure contract in [harness-evaluation.md](harness-evaluation.md) remain the reporting target. Product support and public interfaces determine executable arms; the original abstract matrix does not override observed architecture.

The [first hosted archive inspection](https://github.com/zyw02/agent-arch/actions/runs/40656560031) succeeded: 42 exact-digest accepted native summaries were inspected across four selected archives. [Compact numeric-field inventory](evidence/source-informed-20261028/native-field-inventory.json) confirms that native timings, sampled PSS/RSS and CPU fields exist in relevant summaries. Availability does not establish that their scopes match the new experiment.

`native_read_probe.py` and its hosted workflow now exercise the actual DSH/OpenClaw native `read` tools using protocol-correct synthetic model responses and an unpredictable file receipt omitted from the prompt. It verifies tool-result adoption, final output, unchanged input and explicit installed versions. This is adapter calibration; native/extension matched controls and full resource collection remain pending.
